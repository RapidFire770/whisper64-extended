# Tool question order, line progress, and LF breaks

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The three conversion programs ask each question on the next screen row, paint `LINE n` while a job walks the file, and store an LF as a CR so a labeled SEQ matches the lines the editor loads.

**Architecture:** `tool_take_row` in `src/conv/toolui.c` hands out screen rows. `conv_seq_byte` in `src/conv/token.c` maps LF to CR before a raw SEQ is stored. `conv_set_progress` in `src/conv/renumber.c` paints `LINE n` from the store walks. The editor is not linked to any of this.

**Tech Stack:** C, LLVM-MOS SDK `c64` platform, host `gcc` for `tools/test_renumber.c`. The three tools stay `-Oz`.

## Global Constraints

- The editor is unchanged. No new source file is added.
- `__heap_start` stays at or below `$C800` on `w64conv`, `w64renum`, and `w64label`. `__stack` stays `$D000`.
- `tool_parse_step` is unchanged. An empty field is 10. A typed 0 is passed through and the renumber returns `NUM BIG`.
- `labels_to_numbered_store` and `renumber_seq_store` keep splitting on CR only. The existing host check `no lf split` stays green.
- `tools/test_w64conv_c64u.py` is not run. It resets the Ultimate. A VICE run is not a substitute for the Ultimate check.
- The mount string is `/SD/My Files/W64.d64`.
- Do not commit `.superpowers/`.
